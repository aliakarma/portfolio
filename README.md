# Ali Akarma — Academic Portfolio

> Portfolio of an AI researcher working on agentic AI, trustworthy AI, AI verification and validation (V&V), and secure AI.

**→ Live:** [aliakarma.codes](https://aliakarma.codes/)

---

## How the site stays consistent

All content lives in `data/`. Pages never type in a count, a status label, or a
sentence about the research: they compute it from the data at build time.

- **Counts** (papers, notes, systems, news items) come from `siteCounts()` in `lib/content.js`.
- **Status labels** ("Published · PLoS One") come from `statusLabel()` in `lib/publications.js`.
- **The research graph** is computed from paper tags (`researchGraph()` in `lib/content.js`).
- **The news feed** lists every paper automatically, plus the events in `data/news.js`.
- **Bio, tagline, research vision, and interests** come from `data/profile.js`.
- **Navigation** (navbar, footer, "Keep exploring" cards) comes from `data/nav.js`.

A content check (`lib/validateContent.js`) runs on every `npm run dev` and
`npm run build`. If the data disagrees with itself (an unknown tag, a note
pointing at a missing paper, a duplicate id, a graphical abstract that was
never generated, a malformed date), the build stops and lists what to fix.

## ✏️ Updating content

### Add a new paper

1. Add an entry to the top of `data/publications.js` (published or accepted) or
   `data/underReview.js` (under review). Use a new unique `id` and set:
   - `status`: `published`, `accepted`, or `under_review`
   - `type`: `journal`, `conference`, or `book_chapter`
   - `date`: `"Month D, YYYY"`, e.g. `"November 3, 2026"`
   - `venue` (full name) and `venueShort` (shown on badges)
   - `tags`: only tags listed in `data/tags.js`. To use a new tag, add it there first.
   - `doi`, `pdf`, `code`, `dataset`, `notebook`: links or `null`. For a paper with no DOI, set `doi: null` and put the publisher page in `url`.
   - `coFirstAuthor: true` only if you share first authorship but are not listed first.
2. Optional graphical abstract: put the PNG in `public/graphical-abstracts/`, run
   `npm run images`, and set `graphicalAbstract` to its slug.

That is all. The homepage counts, the venue lists, the research graph, the news
feed, the topic filter, and the structured data all update on the next build.

When a paper moves from under review to accepted, move its entry from
`data/underReview.js` to `data/publications.js` and change `status`.

### Add a research note

Add an entry to the top of `data/blog.js` with a unique `id`, a `date` like
`"2026-11-03"`, and `publicationId` set to the paper's `id`. The note then shows
the paper's venue and links to it, and the paper's card links back to the note.

### Add a project

Add an entry to `data/projects.js`. If it belongs to a paper, set
`publicationId`; its status and paper link then follow that paper. If not, set
`publicationId: null` and a `status` (`Open Source`, `Research`, or `Under Review`).

### Add a news item that is not a paper

Add it to `data/news.js` (internships, talks, awards). Papers appear in the
news feed on their own; do not add them here.

### Change how the research is described

Edit `data/profile.js`: `headline`, `summary`, `thesis`, `bio`, `researchVision`,
`researchInterests`, `heroLines`, `currentFocus`, `collaboration`, `expertise`.
Every page, meta description, and the schema.org data read from these fields.

### Change the research graph

Themes are listed in `data/researchThemes.js`; each is one tag from
`data/tags.js`. Add or remove a theme there. Sizes, counts, and links are computed.

### Add a page

Create it in `pages/`, add it to `data/nav.js` (navbar, footer, and explore
cards), and to the route list in `scripts/generate_sitemap.js`. Return
`counts: siteCounts()` from its `getStaticProps` so the explore cards show numbers.

## 🗂 Repository Structure

```
portfolio/
├── data/                        ← All content lives here
│   ├── profile.js               ← Bio, research description, education, experience, awards
│   ├── publications.js          ← Published and accepted papers
│   ├── underReview.js           ← Manuscripts under review
│   ├── blog.js                  ← Research notes (one per paper)
│   ├── projects.js              ← Research systems and code
│   ├── news.js                  ← Non-paper milestones
│   ├── tags.js                  ← Allowed publication tags and their colours
│   ├── researchThemes.js        ← Themes drawn in the research graph
│   ├── nav.js                   ← Pages, in menu order
│   ├── site.js                  ← Site URL and shared image URLs
│   ├── scholar.json             ← Google Scholar metrics (automated)
│   └── graphicalAbstracts.json  ← Generated by npm run images
│
├── lib/
│   ├── publications.js          ← Publication helpers (status label, sorting, first author)
│   ├── content.js               ← Build-time derivations: counts, news, graph, cross-links
│   ├── validateContent.js       ← Content check that fails the build on inconsistencies
│   └── jsonld.js                ← Safe JSON-LD serialisation
│
├── components/                  ← Navbar, Footer, ExploreNext, PublicationCard, ResearchGraph, …
├── pages/                       ← index, about, research, projects, blog, news, contact, 404
├── scripts/                     ← sitemap, Scholar metrics, image optimisation
└── public/                      ← Profile photo, CV, graphical abstracts
```

## 🚀 Quick Start

Requires **Node.js 20+**.

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # static export to out/
npm run lint
```

The site is a static export (`output: 'export'` in `next.config.js`) and is
deployed on Vercel, which builds on every push.

## 📊 Google Scholar Metrics

The portfolio reads citations, h-index and i10-index from the metrics table on the
public Google Scholar profile and displays them on the homepage.

**Google Scholar is the only source.** Other bibliographic databases index a
smaller slice of the literature, so mixing them in produced figures that
disagreed with the profile the site links to.

**Automated Updates:**
- ✅ Scheduled weekly via GitHub Actions (`.github/workflows/update_scholar.yml`)
- ✅ Runs `npm run scholar:update`, retrying up to 3 times across Scholar mirrors
- ✅ `data/scholar.json` is only written after a clean read — a blocked fetch never overwrites good numbers
- ✅ `lastUpdated` is refreshed on every successful read, so the date on the site means "confirmed against Scholar on"
- ⚠️ If all attempts are blocked the workflow **fails on purpose**, so GitHub notifies you to update manually

**Manual Update (if the workflow fails):**

Google Scholar rate-limits datacenter IPs and GitHub's runners share a pool of
them, so scheduled runs can be blocked. Two ways to fix it:

```bash
# From your own machine, where Scholar is usually reachable:
npm run scholar:update

# Or type the numbers in by hand, from
# https://scholar.google.com/citations?user=kQZZJtYAAAAJ
npm run scholar:manual -- <citations> <hIndex> <i10Index>

# Example:
npm run scholar:manual -- 57 5 2
```

**Update File Directly:**

Edit `data/scholar.json`:
```json
{
  "citations": 119,
  "hIndex": 8,
  "i10Index": 5,
  "lastUpdated": "2026-08-25T11:05:08.601Z",
  "source": "google_scholar",
  "fetchFailed": false
}
```

**Notes:**
- `citations` — Total number of citations across all publications (Scholar's "All" column)
- `hIndex` — H-index (papers with ≥ h citations each)
- `i10Index` — i10-index (papers with ≥ 10 citations each)
- `lastUpdated` — ISO timestamp of the last confirmed read
- `source` — `google_scholar` (scraped) or `manual` (typed in)
- `fetchFailed` — Flag indicating if automated fetch failed

After updating, commit the changes:
```bash
git add data/scholar.json
git commit -m "update: scholar metrics"
git push
```
